# 文章ガイド

BMZ Player の利用者向けの文章（ゲーム内の設定説明・通知、[マニュアル](../manual/README.md)、
IR Web の案内文）を書くときの基準です。`docs/` の開発者向け仕様には適用しません。

## 読み手

- BMS を初めて遊ぶ人が、用語集を見ながら読み進められることを目安にします。
- LR2 / beatoraja の経験者には、違いだけを短く示します。

## 文体

- です・ます調で、落ち着いた説明にします。「〜しましょう」「〜してみてください」は多用しません。
- 1文に1つの内容を書きます。日本語で60字前後を超えたら分けられないか検討します。
- 主語や対象を省略しすぎないようにします（「これを変更すると」ではなく「ゲージを変更すると」）。

## 書く内容

設定の説明は、次の順で必要なものだけを書きます。

1. その設定で何が変わるか
2. どういうときに変えるか、迷ったときのおすすめ
3. 変更が反映されるタイミングなど、知らないと困る注意点

項目名をそのまま言い換えただけの説明（「ゲージ：使用するゲージを選びます」）は書きません。
書くことがなければ、説明を空にしたほうが読みやすい場合もあります。

## 書かない内容

- 実装の経緯や以前のバージョンとの比較（「従来どおり」「新しい項目」「〜を維持します」）
- 内部名・設定ファイルのキー・crate名・feature名（`rule_mode`、`gilrs` の Button 番号など）
- 開発や計測でしか使わない情報。必要なら `docs/` の仕様へ置きます。

## 用語

- 判定名やオプション名は、ゲーム画面の表記に合わせます（`PGREAT`、`EX SCORE`、`HARD`、`S-RANDOM`）。
- 一般の人が知らない用語（緑数字、CN、閉店など）は、マニュアルの[用語集](../manual/ja/08-glossary.md)へ載せます。
- 同じものを別の言葉で呼びません。画面の表記を優先し、マニュアルもそれに合わせます。
- 画面上の操作は「設定 → ライブラリ → 曲フォルダ」のように、実際に押す順に書きます。

## 例

| 悪い例 | よい例 |
| --- | --- |
| プレイ開始時に使用するゲージを選びます。 | ゲージの増え方・減り方とクリア条件が変わります。初めての方は NORMAL、クリアが難しい曲は EASY がおすすめです。 |
| GPUのPresent Modeを選び、ティアリングと表示遅延のバランスを調整します。 | 画面のちらつき（ティアリング）を防ぐかどうかを選びます。防ぐ設定にすると、表示がわずかに遅れます。 |
| 既定のAutoは従来動作のままです。 | （書かない） |

## 英語版

- 日本語版と同じ内容を、自然な英語で書きます。直訳で不自然になる場合は言い換えます。
- 命令形や二人称（"Choose ..."、"You can ..."）を使い、簡潔にします。
- 韓国語・中国語のカタログは、日本語・英語を更新したあとに別作業で追従します。

## マニュアルの管理

- マニュアルの原稿は `manual/<言語>/NN-slug.md` に置きます。詳しくは [manual/README.md](../manual/README.md) を参照してください。
- 仕様を変えたときは、`docs/` の仕様に加えて、マニュアルとゲーム内の説明も確認します。
